# Automatic RTK and clearer Headroom measurements

The approved bundle command hook now routes simple native Windows `git status`, `git diff`, `git log` and `rg` calls through RTK when the bundled launcher is enabled and on PATH. It preserves literal arguments and executes the command once. It skips scripts, chains, pipelines, computed arguments, WSL paths, machine-readable formats, binary patches, whitespace checks and exact-output requests. Existing explicit RTK calls are not wrapped again. Custom shell aliases are outside this native-command contract; use the exact-output opt-out when the original shell command must run.

RTK and local Headroom toggles remain independent. `HEADROOM_EXACT=1` or a `# rtk: exact` / `# headroom: exact` command comment bypasses automatic rewriting. Existing trusted hook registration stays unchanged, so updating its installed script applies to existing tasks. Fresh team installations register the hook for review; the user must trust it once in Codex Settings. The installer never grants trust and preserves explicitly disabled hooks and unrelated definitions.

The Headroom dashboard now shows eligible-content reduction and complete-input reduction side by side using one backend snapshot. These counters are independent of the selected recent/lifetime savings window. Recorded WebSocket failures and compression timings are shown separately; a failed frame is not automatically labeled a timeout. Missing, invalid or inconsistent data is unavailable rather than fabricated.

A narrowly guarded Headroom 0.37 HTTP accounting fix includes classic tool schemas in the before/after token pair. It corrects impossible percentages without changing request payloads, saved-token totals, model or reasoning. WebSockets and `additional_tools` remain on their existing accounting path. Additional counting has a 100 ms deadline and runs off the event loop; failure preserves the original outcome. Future SDK versions stay on their native implementation.

Compression deadlines, exact-original protection and native Codex compaction remain unchanged. The desktop's cumulative-accounting behavior was not copied because it would redefine this bundle's per-request totals. These estimates do not establish actual Codex quota savings or identical LLM answers.
