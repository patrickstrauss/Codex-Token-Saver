# Symbol-aware retrieval candidates for Codex Token Saver

Research checked 14 September 2026. This is a recommendation only; no software, configuration, hooks, or routing were changed. GitHub API and raw files were fetched directly because the web search tool failed to decode responses.

## Recommendation

**Serena is the stronger candidate of these two for an optional, project-scoped navigation integration.** It adds language-aware symbol and reference lookup before content enters the context window. RTK reduces command output and Headroom compresses content already selected for requests; Serena can avoid selecting irrelevant source in the first place. These benefits overlap, so their displayed savings must not be added together.

Start with navigation only: symbol overview, symbol lookup with bodies requested only when needed, and reference lookup. Keep native exact file reads/patches available. Do not enable a second broad command/file tool suite or automatic semantic edits by default. Validate against a real Windows checkout and Codex worktree before broad rollout.

### Serena

- **License:** MIT, confirmed from the repository license and GitHub API. Suitable for a bundle subject to preserving its notices. [License](https://github.com/oraios/serena/blob/main/LICENSE)
- **Maintenance:** repository not archived; latest published release reported by the GitHub API was **v1.7.0, 9 August 2026**; last push **12 September 2026**. Main's package version was `1.7.1.dev0`. Use a pinned release, not an unpinned main branch. [Release](https://github.com/oraios/serena/releases/tag/v1.7.0), [package metadata](https://github.com/oraios/serena/blob/main/pyproject.toml)
- **Windows:** Python package supports 3.11–3.14; official install recommends `uv tool install -p 3.13 serena-agent`, then `serena init` for its language-server backend. CI explicitly includes `windows-latest`, although some language batches are excluded on Windows. This is native Windows support, not a reason to require WSL. Individual language servers need separate prerequisites. [Installation](https://github.com/oraios/serena/blob/main/docs/02-usage/010_installation.md), [Windows CI matrix](https://github.com/oraios/serena/blob/main/.github/workflows/pytest.yml)
- **Codex Desktop explicitly documented:** upstream has a “Codex (CLI and App)” section, offers `serena setup codex`, and documents `start-mcp-server --project-from-cwd --context=codex`. Its documentation warns that the Codex app may not start sessions in the project's directory and recommends activating the project explicitly. Our integration should choose the actual checkout/worktree per task rather than assume the process working directory. Do not run the upstream auto-setup blindly over the managed bundle's configuration. [Codex instructions](https://github.com/oraios/serena/blob/main/docs/02-usage/030_clients.md#codex-cli-and-app)
- **Avoid duplicate schema overhead:** the Codex context excludes `create_text_file`, `read_file`, `execute_shell_command`, `replace_content`, `find_file`, and `list_dir`. Tools can be further enabled/disabled through project/configuration contexts. Tool schemas and instructions still consume context; no universal fixed overhead or end-to-end savings percentage was established in the reviewed documentation. [Codex context](https://github.com/oraios/serena/blob/main/src/serena/resources/config/contexts/codex.yml), [configuration](https://github.com/oraios/serena/blob/main/docs/02-usage/050_configuration.md)
- **Exactness:** `find_symbol` defaults `include_body=False`; source bodies are opt-in, with `max_matches` and `max_answer_chars` limits. Symbolic navigation uses language intelligence rather than an LLM-generated substitute for the source. Nevertheless, an overview is not complete source evidence, and language-server/worktree freshness must be tested. Use exact source for edits and preserve the bundle's exact-output protection. [Tool source](https://github.com/oraios/serena/blob/main/src/serena/tools/symbol_tools.py)
- **Benefit is workload-dependent:** upstream's GPT-5.4/Codex Java evaluation reports useful precise references and structural navigation but says tiny intra-method edits are smaller with built-in patches and entire method replacements still send entire method bodies. That evaluation uses its JetBrains backend, so do not treat it as a measured savings percentage for the Windows language-server setup. [Evaluation](https://github.com/oraios/serena/blob/main/docs/04-evaluation/030_results/020_codex_on_jbplugin.md)
- **Prerequisites can expand:** TypeScript/JavaScript use TypeScript language-server support; PowerShell support requires PowerShell 7+ and downloads PowerShell Editor Services/PSScriptAnalyzer; Rust requires rustup. Install only needed languages and surface downloads/dependencies in the updater. [Language support](https://github.com/oraios/serena/blob/main/docs/01-about/020_programming-languages.md)

### jCodeMunch-MCP

**Do not include by default in an open-source bundle.** Its current source is available, but its license is not a conventional permissive open-source license.

- Current **Dual-Use License v1.1, effective 30 June 2026**, permits free non-commercial use and requires a commercial license for revenue-supporting workflows. It also limits redistribution, forbids public-registry distribution without permission, and restricts renaming/repackaging. Those terms matter directly to a reusable app bundle. This conclusion is based on the text of the license, not on the GitHub “NOASSERTION” label alone. [License](https://github.com/jgravelle/jcodemunch-mcp/blob/main/LICENSE), [README licensing section](https://github.com/jgravelle/jcodemunch-mcp#licensing-and-commercial-use)
- Active project: latest published release from the API was **v1.108.318, 11 September 2026**; last push **14 September 2026**. [Release](https://github.com/jgravelle/jcodemunch-mcp/releases/tag/v1.108.318)
- It offers indexed symbol retrieval, exact symbol-source retrieval, session statistics, and Codex CLI/MCP setup. Explicit Codex Desktop documentation was not established in the reviewed client guide; stdio MCP compatibility alone is not evidence that desktop/worktree activation has been tested. [Clients](https://github.com/jgravelle/jcodemunch-mcp/blob/main/CLIENTS.md)
- Its own September 2026 benchmark reports **28.3× fewer retrieval tokens** over 15 task-runs versus reading three grep-ranked whole files: 664,975 versus 23,467 tokens. This is a retrieval benchmark, not total Codex usage, and not against our RTK+Headroom stack. Its methodology explicitly does not measure answer quality, latency, or end-to-end task completion; AI summaries were disabled. Do not promise 96.5% overall savings. [Benchmark and methodology](https://github.com/jgravelle/jcodemunch-mcp/blob/main/benchmarks/METHODOLOGY.md), [headline table](https://github.com/jgravelle/jcodemunch-mcp#reproducible-token-efficiency-benchmark)
- Schema overhead is material: configuration documents 91 canonical tools, 90 exposed in the full profile with the diagnostic summarizer disabled. New install helpers initialize a compact core profile with a CI-enforced **4,000-token schema ceiling**; the code fallback remains full. The core profile and disabled AI summaries would be required for a meaningful comparison. [Configuration](https://github.com/jgravelle/jcodemunch-mcp/blob/main/CONFIGURATION.md)

## Validation before integrating Serena

1. Use the same existing repository, model, task prompts and Headroom/RTK settings for baseline and candidate runs.
2. Include locating a function, finding actual references, a small bug fix, a tiny known-line edit, and a non-code task. Measure all tool schemas/instructions, input/output tokens, extra searches, task correctness and elapsed time—not just a symbol-body versus whole-file estimate.
3. Verify the selected checkout, multi-worktree isolation, source freshness after edits and renames, and byte-exact symbol body recovery. Ensure Headroom does not recompress a response claimed to be exact.
4. Record source-selection estimates separately from downstream Headroom estimates; report actual end-to-end task usage separately, avoiding double counting.
5. Pin package/language-server versions, integrate health checks and rollback with the existing library updater, and keep the managed request route unchanged.
