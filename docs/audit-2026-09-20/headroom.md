## Smallest repairs for the later build

- Fix supervisor lifecycle and recovery first; log supervisor termination/errors, expose heartbeat age, and verify owned PID identity before treating saved status as live. Reproduce boot/logon, sleep/resume, worker exit and supervisor exit using isolated fixtures, then a user-authorized managed restart when appropriate. Avoid restarting active sessions merely to refresh counters.
- Show requested state separately from effective state: Enabled + Bypassed (backend offline), Disabled, Running, Error, and Last used. Explain current bypass prominently rather than relying on an old savings total or a generic Configured badge.
- Use a fresh authoritative last-activity timestamp for ledger freshness and keep last-positive-saving time distinct. Keep cumulative connection counts separate from model request counts; one WebSocket may carry many requests.
- Implement independent RTK, local-output Headroom, and request Headroom controls through existing managers, with pass-through behavior when disabled. Do not conflate disabling local stdout filtering with disabling the request proxy.
- Preserve signed local overhead, retrieval costs, and the separation of local savings from repeated request savings. Never add those counters into a purported quota-saving total. Cached tokens and avoided input tokens do not equate directly to Codex weekly quota.
- Require exact retrieval round-trip checks against the **running** backend, matching source fingerprints and process identity. Surface retrieval unavailability explicitly; do not treat a stale startup receipt as healthy.

## Quality and integration limits

The local SDK and request proxy are distinct compression stages. Already reduced RTK stdout may enter local Headroom and later request Headroom again. Counters at each stage are not independently additive. Lossy compression cannot be guaranteed to preserve every future question; use realistic A/B fixtures before changing aggressiveness, including error lines, code syntax, schemas, Unicode, CRLF, failed commands, nested tool results, and exact original retrieval. Preserve user/system instructions, model/reasoning settings, tool identity and exact machine-readable paths. Measure useful end-to-end token reduction alongside retrieval overhead, output correctness, latency and fallback rate. Current outages should be repaired before adding another optimizer.
