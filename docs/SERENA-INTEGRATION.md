# Serena navigation

Enabling Serena also installs an idempotent managed block in the global `$CODEX_HOME/AGENTS.md` (default `~/.codex/AGENTS.md`). It directs coding tasks to activate their current checkout automatically and prefer symbol overviews, definitions and references for relevant navigation, with exact bodies before edits. The MCP server supplies the same self-contained guidance within Codex's 512-character server-instruction limit. New tasks need no repeated Serena setup prompt. Existing tasks may need to reload their MCP connection to receive new server instructions.

Disabling removes only this managed guidance block and Serena's managed MCP entry, preserving other guidance bytes and settings. Configuration and guidance are backed up before changes; failed destination writes restore the prior files and live preference, preserving concurrent external edits. The live toggle continues to block new calls in already loaded tasks. Unsupported languages or failed navigation fall back to native source tools. This is automatic tool-selection guidance, not transparent interception or a guarantee that every code read uses Serena.

The managed MCP entry point remains `serena_mcp.py`. It launches the official isolated Serena runtime through a standard MCP bridge, exposing only `activate_project`, `get_symbols_overview`, `find_symbol` and `find_referencing_symbols`. Both the upstream context and the bridge enforce this fixed tool set. Activating a project cannot expose editing tools. Project selection requires an explicit absolute checkout path; home directories and drive roots are rejected.

Each new tool call reads `settings/components.json`. Turning Serena off blocks subsequent calls even in an already loaded Codex task. A call already dispatched may finish. A malformed preference file also blocks new calls. Existing idle MCP/LSP processes may remain until Codex reloads them; the switch controls use, and is not a promise to immediately unload processes.

Exact symbol bodies and reference results carry the bundle's existing authenticated exact-response receipt, so a running, validated Headroom request backend preserves them rather than applying another lossy compression pass. Normal overviews remain overviews. Native source tools remain available if the language server cannot resolve a symbol.

The bundle records completed/failed/blocked counts, per-tool counts and total elapsed milliseconds, latest call duration, and a dated failure category in `serena/activity.json`. The fixed categories are `missing_path`, `no_project`, `timeout` and `upstream_error`; query arguments, project paths, source text and raw error messages are never added to this ledger. Existing totals are preserved when upgrading, but per-tool timing starts with the updated bridge. Durations measure the upstream lookup and exact-response protection, not added overhead compared with native tools. Blocked calls add no lookup duration. The last failure remains visible after a successful call and must be interpreted with its timestamp. Official Serena keeps its own local logs and project state. No synthetic token savings are claimed for navigation.

Failed tool results retain the upstream error and add a specific next step. A missing-path result asks Codex to verify the path relative to its active checkout and reactivate the correct checkout if needed; an absent project asks it to activate the current checkout directly. Native file/search tools are always available as a fallback. The bridge does not retry a failing lookup or read arbitrary files automatically. The September 2026 performance audit's failed overview was an upstream `FileNotFoundError` for a path that did not exist in the selected project, not evidence of a language-server crash.

Each Codex MCP connection has its own Serena process and active-project state. Language servers start on project activation, while the web dashboard and GUI are disabled. Several open connections can therefore use substantial memory; the audit measured about 1.8 GB across all Serena-related processes, not per task. The MCP client's existing stdio cleanup closes the upstream connection gracefully and handles process-tree termination on Windows when needed. Idle processes may persist as long as Codex keeps their connections open. The bundle deliberately does not pool mutable project state across tasks or kill idle language servers without restoring that state. Turning Serena off blocks new queries but does not interrupt an in-flight lookup or guarantee immediate process unloading.

Updater compatibility remains `probe_runtime(root, python_path)`. Candidate validation initializes the official server directly and verifies exactly the four tools even when the component is off. Normal tool use always passes through the live preference gate.

`scripts/verify_serena_navigation.py` checks real Python and TypeScript overviews, exact bodies, callers, source freshness after a file edit, stable tool exposure after activation, and off/on behavior in the same MCP session. It creates a temporary bundle and project while reading already installed Serena dependencies. Use the installed Serena interpreter to run it; `--bridge-python` can select the separate interpreter Codex uses for the bridge. No Codex configuration or production project is modified.
