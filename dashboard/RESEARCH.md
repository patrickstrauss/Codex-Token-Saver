# Token-saving and monitoring alternatives

Checked September 13, 2026 against the projects' own repositories. The follow-up review identified **Serena as the strongest next candidate for coding tasks**, with ast-grep as a lighter structural-search option. Keep RTK + Headroom, the installed local dashboard, and the bundle's tray host as the baseline. Add another compressor only after measuring a specific gap: overlapping output interception can add tool schemas, caching state, and extra recovery calls without proving lower account usage.

## Follow-up candidates (researched, not installed)

- **[Serena](https://github.com/oraios/serena), MIT:** semantic symbol lookup, references, and targeted editing can avoid broad file reads. The [official Codex integration](https://oraios.github.io/serena/02-usage/030_clients.html#codex-cli-and-app) supports CLI and desktop. Current installation is `uv tool install -p 3.13 serena-agent`, followed by `serena init` and client setup. Windows is tested, but language servers bring language-specific dependencies. Recommendation: test it on one code project first and compare total tokens and correctness against the existing bundle. This complements compression by retrieving less code in the first place.
- **[ast-grep](https://github.com/ast-grep/ast-grep), MIT:** syntax-aware code search with Windows distributions. Its [outline command](https://ast-grep.github.io/guide/outline-code) produces compact source maps without an index or language server. Outline remains alpha (introduced in 0.44.0), and syntax matching does not resolve semantic types/references. Recommendation: lightweight alternative for structural searches; avoid installing both it and Serena without a concrete workflow need.
- **[Microsoft LLMLingua-2](https://github.com/microsoft/LLMLingua), MIT:** model-based prompt compression for longer text. It requires PyTorch and a compressor model, adds runtime resources, and would need an integration path. The installed Headroom release removed its old unused LLMLingua extra; its supported optional ML path is Kompress/ModernBERT. Recommendation: defer a separate LLMLingua integration. Benchmark the existing Headroom ML option first if structural compression proves insufficient; it is currently disabled to keep the background bundle lighter.

Tree-sitter 0.26.0 and tree-sitter-language-pack 0.13.0 are already installed in Headroom's isolated environment for code-aware compression. A second bare parser installation would not automatically reduce Codex token usage. ccusage remains a useful companion for local usage measurement, not a compressor.

Also verified [RTK Inspector](https://github.com/petermefrandsen/rtk-inspector) (MIT), a VS Code dashboard reading `rtk gain` plus Codex logs. Install with `code --install-extension PeterMEFrandsen.rtk-inspector` if VS Code is already used. It is not a standalone Windows tray and duplicates the chosen dashboard. Its cross-tool percentage is its own analytic formula, not a measured subscription saving.

The installed dashboard's source and local changes remain reviewable. [RTK's own analytics guide](https://github.com/rtk-ai/rtk/blob/develop/docs/guide/analytics/gain.md) explicitly describes estimated output reduction, not an equivalent reduction in a bill or provider quota. Percentages from different compressors should not be added.
