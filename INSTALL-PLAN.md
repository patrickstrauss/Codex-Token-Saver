# Codex Token Saver desktop architecture

Use `%USERPROFILE%\CodexTokenSaver` as the stable installation root. A regular user folder avoids the Codex MSIX virtualization that affected the earlier `%LOCALAPPDATA%` installation. Recreate Python environments at the new location; preserve data and backups.

- **Desktop connection:** keep the normal connection, model, reasoning settings, and authentication. Never install or automatically re-enable global Headroom routing.
- **Desktop Headroom tools:** register the local stdio server `headroom_desktop` with `required=false`. Codex starts `desktop_mcp.py` using the installed Headroom Python environment. `desktop_headroom.py` uses the installed SDK offline, with telemetry disabled and a local tokenizer cache. This compresses selected initial large JSON, CSV, and log file reads; it does not compress all conversation traffic.
- **Exact retrieval:** expose `headroom_read_file`, `headroom_retrieve`, and `headroom_stats`. Preserve exact originals for up to 24 hours in `headroom\desktop-state\originals.db`; retrieve originals or use `compress=false` before exact edits, quotations, or completeness-sensitive decisions. Fall back to ordinary file tools if the server is absent or fails.
- **Registration:** `install_desktop_mcp.py` adds the optional server and usage guidance, preserving unrelated configuration. `desktop-integration.json` is a registration receipt, not runtime evidence. Restart Codex and begin a new session to load the tools; do not assume an existing task has refreshed its tool list.
- **RTK:** native `bin\rtk.exe` invokes `tools\rtk.exe` with history at `data\rtk\history.db`; `bin\rtk.cmd` is legacy only. Preserve command arguments and imported history; isolate synthetic fixtures.
- **Default services:** dashboard on `127.0.0.1:8095` and Windows tray. Recovery must not change desktop routing.
- **Optional CLI proxy:** `127.0.0.1:8787` for explicit experiments, separate from the desktop tools. Native `bin\codex-headroom.exe` applies routing to one CLI process, falls back to direct mode if prelaunch checks fail, and never automatically replays a run after it begins. Native `bin\codex-saver.exe` stays direct. Both preserve literal arguments without shell forwarding.
- **Login startup:** `Install-Startup.ps1` attempts a user-logon scheduled task and provides a Windows Startup shortcut fallback. Register from the regular folder through Explorer; inspect `install-startup-result.json` for the actual outcome.
- **Savings:** show three separate dashboard/tray counters: RTK, desktop Headroom, and CLI proxy history. Desktop `headroom\desktop-state\activity.db` records read and retrieval events. Net savings include returned text headers, subtract expansion and retrieval output, and may be negative; expose positive gross read reduction and retrieval counts separately. MCP framing and model usage are excluded. Preserve the original proxy record of 234 reduced tokens as history. Never sum incompatible counters or present them as quota/billed savings.
- **Open the app:** Windows Start menu **Codex Token Saver**, the TS tray icon, or `http://127.0.0.1:8095/` opens the dashboard. Existing startup path repair remains in place.

Verification targets: offline SDK/tokenizer initialization; optional MCP startup and failure isolation; compressed read and exact retrieval across process restart; original expiry; signed accounting including returned headers and retrieval costs; configuration preservation; native RTK argument fidelity and stable database placement; dashboard/tray status and independent proxy history. Synthetic validation must use separate state so it cannot inflate real counters.

Earlier service checks cover optional-proxy prelaunch fallback and no replay, loopback service identity, tray recovery, and startup registration/readback. The historical `REPAIR-REPORT.md` is not evidence that the current desktop MCP tools loaded in an already-open task. A true reboot/login test remains outstanding.
